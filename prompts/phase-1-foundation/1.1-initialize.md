# Implementation Prompt: Phase 1 - Foundation (Repo Setup)

## 1. Goal
Initialize the monorepo foundation for Vibelearn by setting up the decoupled `frontend` and `backend` workspaces according to `docs/roadmap.md` and the architecture specifications in `docs/system_design/`. This establishes the project directory structure, Vite React frontend with Tailwind CSS, Express backend, code quality tools (ESLint & Prettier), and environment configurations.

## 2. Skills Read
- Checked available skills: `antigravity-guide`, `agy-customizations`. No domain-specific project skills required for repo initialization.

## 3. Code & Documents Inspected
- `AGENTS.md`: Strict rules on workflow, prompt creation, tech stack, and reporting.
- `docs/roadmap.md`: Phase 1 tasks 1.1 through 1.7.
- `docs/system_design/frontend.md`: Architecture rules, folder structure, mobile responsiveness, and prohibition of direct DB access.
- `docs/system_design/backend.md`: Layered architecture (`Routes -> Controllers -> Services -> Repositories`), error handling, and folder structure.
- `docs/system_design/architecture.md`: Strict rule: **No TypeScript** (standard JavaScript only) and **No Docker/Containerization**.
- `docs/system_design/database.md`: Database entities and relationships.
- `docs/prd.md`: Product scope and user flows.

## 4. Decisions & Assumptions
- **Language:** Standard JavaScript (ES modules) across both `frontend` and `backend` (TypeScript is strictly forbidden per `architecture.md`).
- **Frontend Stack:** React 19 / 18 bootstrapped via Vite with `@vitejs/plugin-react`, Tailwind CSS v3 with PostCSS and Autoprefixer, `tailwind.config.js`, and standard folder structure matching `frontend.md`.
- **Backend Stack:** Node.js Express server (`"type": "module"`), `cors`, `dotenv`, running on port 5000 with a `/health` endpoint for readiness checking.
- **Linting & Formatting:** ESLint with standard JS/React plugins and Prettier configured in both `frontend` and `backend`.
- **Environment Stubs:** `.env.example` created in both `frontend` and `backend` documenting all needed variables (Clerk, Supabase, API URLs) without committing any secrets.

## 6. Requirements
- **Task 1.1:** Initialize `frontend` folder with Vite (React, JavaScript).
- **Task 1.2:** Initialize `backend` folder with Node.js (Express, JavaScript).
- **Task 1.3:** Setup TailwindCSS in `frontend` with `tailwind.config.js`, `postcss.config.js`, and base directives in `src/index.css`.
- **Task 1.4:** Configure ESLint and Prettier across both `frontend` and `backend`.
- **Task 1.5:** Create `.env.example` in both `frontend` and `backend` with required stubs.
- **Task 1.6:** Verify both dev servers start without errors via `npm run dev`.
- **Task 1.7:** Checkpoint verification and update `docs/roadmap.md`.

## 7. Security Considerations
- No production secrets or real API keys stored in `.env.example` or code.
- CORS configured properly in backend for frontend dev origin (`http://localhost:5173`).
- Frontend and backend strictly decoupled.

## 8. Acceptance Criteria
1. `frontend/` contains a working React + Vite + TailwindCSS application adhering to `docs/system_design/frontend.md`.
2. `backend/` contains a working Express application adhering to `docs/system_design/backend.md`.
3. `npm run lint` passes with 0 errors in both `frontend` and `backend`.
4. `npm run dev` starts the frontend server on `http://localhost:5173`.
5. `npm run dev` starts the backend server on `http://localhost:5000` and `GET http://localhost:5000/health` responds with `{"status":"ok"}`.
6. Both workspaces have `.env.example` with clear placeholders.
7. `docs/roadmap.md` is updated with checkboxes checked for tasks 1.1 - 1.6 upon successful execution.

## 9. Checks to Run
- `cd frontend && npm run lint`
- `cd backend && npm run lint`
- Start frontend dev server and verify HTTP 200 response
- Start backend dev server and verify `GET /health` returns HTTP 200 with `{ "status": "ok" }`

## 10. Manual Test Steps
1. Navigate to `frontend` directory: run `npm run dev`.
2. Open `http://localhost:5173` in browser: verify Vibelearn placeholder page loads with Tailwind styling applied.
3. Navigate to `backend` directory: run `npm run dev`.
4. Open `http://localhost:5000/health` in browser or curl: verify response is `{"status":"ok"}`.
5. In both directories, run `npm run lint` and verify clean output.
